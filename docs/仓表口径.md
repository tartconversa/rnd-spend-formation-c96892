# 仓表与口径实现说明

本文说明 `rdwarehouse` 包如何把 `docs/资料口径.md` 的来源语义落成可持续装载、
重算和查询的仓表。规则仅用于内部管理，不生成正式会计凭证或税务申报。

## 1. 分层与表清单

| 层 | 表 | 性质 |
| --- | --- | --- |
| 批次 | `load_batch`, `loaded_file` | 接收批次、文件指纹（sha256），同摘要不产生事实 |
| 原始层 | `raw_orders` … `raw_revisions`（10 张） | 只追加，整行修订保留全部历史版本 |
| 事实层 | `fact_line_state`, `fact_formed`, `fact_document`, `fact_return_link`, `fact_asset_cost`, `fact_asset_schedule`, `fact_asset_alloc`, `fact_project_measure`, `fact_exception` | 按批次视野从 raw 全量重算，可幂等重建 |
| 管理包 | `pkg_header`, `pkg_measure`, `pkg_line`, `pkg_asset`, `pkg_exception` | 按月冻结的快照，确认后不可变 |

原始层物理列在契约列名外增加 `_batch / _file / _row`；`organizations.end`
在物理表中为 `end_date`（DuckDB 保留字），经装载器映射回契约名 `end`。

金额在原币事实中保留精确 `DECIMAL`，全程禁止 float（`rdwarehouse.money.D`
遇到 float 直接报错）。到分结算用 `ROUND_HALF_UP`，尾差归分摊基数最大项、
并列按业务键升序、待分行（project 为空）最后。

## 2. 三种口径为什么不是一个金额列

`fact_line_state` 对每个采购行、每个业务月同时保存互相独立的量：

- **承诺（未履约）** `commitment_*`：有效订单量减净收货，乘以订单单价。
  订单修订（`revisions`）只能减少这一部分；修订量低于已验收义务时，
  已形成量不回退，冲突进 `fact_exception`（RV1 场景：40 < 已验收 50，
  冲突 10 件，承诺为 0 而形成仍为 500 元）。
- **待核义务（已实收未验）** `pending_*`：净收货减累计验收，独立于承诺，
  退货不能把它退回成未履约预算。
- **验收形成** `formed_*`：验收日按当天汇率折人民币；consumable/service
  为当期费用，equipment/installation 先归在建资产。
- **票据** `invoice_* / credit_* / invoice_net_*`：invoice 与 credit 各自独立，
  红冲不靠负号。
- **现金** `payment_* / refund_* / cash_net_*`：付款与退款各自独立。
- 桥接差额：`unsettled_* = 形成 - 票净额`（已形成未结算），
  `prepaid_* = 现金净 - 票净额`（预付），三口径汇兑差
  `formed_fx_var / invoice_fx_var / cash_fx_var` 分别可区分。

桥接恒等式（人民币，任一组成部分缺汇率则整体为 NULL 而非 0）：

```
承诺 + 待核 + 形成 = 有效订单人民币价
票净额 + 已形成未结算(unsettled) = 形成
票净额 + 预付(prepaid) = 现金净
```

`Queries.budget_occupation` 直接给出每行的三口径与校验列，
校验列非 0 即说明桥接不平。

## 3. 退货、红冲、退款的独立性

三类凭据在 `fact_document` / `fact_return_link` 中各走各的链路，
不会因为出现负金额就互相认定：

- 无任何在先收货的退货 → `unlinked_pending`，整笔列待核；
- 多笔候选收货且来源无明确关联 → `ambiguous_pending`，不任意选取；
- 退货冲及已验收量 → `linked_partly_accepted` + warning，已验收义务不自动减少，
  须独立核对（资料口径明确要求后续资料给出退货与原收货/已验收份额的关联）。

## 4. 汇率与汇兑差额

- 只认业务当天汇率（`fx`），缺日不插值，CNY 恒为 1；
- 承诺用订购日汇率，形成用验收日汇率，票据/现金用各自单据日汇率；
- 缺当天汇率时原币金额照常落表，人民币金额为 NULL 并写
  `fx_missing` 例外，下游 NULL 传播（不用 0 顶替，避免把"未知"伪装成"无发生")；
- 各口径汇兑差 = 该口径按业务时点汇率的人民币额 − 按订购日基准汇率折算额，
  因此价格差异（数量/单价变化）与汇兑差额天然分离。

## 5. 资产：启用前归集、直线分担、后补重算、共享分摊

1. **归集判定按实际服务发生日（收货日）而非发票日**：收货日早于
   `asset.ready_at` 为启用前成本，进 `fact_asset_cost.pre_enablement`。
2. **直线分担**：启用当月不分担，次月开始；月额 = 当期基数 / 剩余月数
   （36 月、无残值）。月额到分，月度间不做余额滚动调整。
3. **后补启用前成本**：以验收接收月为补齐月（不早于启用次月）开启新分段，
   从补齐月起按新基数对剩余月数重算月度额；已确认的旧管理包内容不改。
   已支付现金只挂 `prepaid`，验收形成前不记支出。
4. **共享分摊**：同资产同月 `coverage_fraction` 必须一致（不一致进例外）；
   项目份额 = 该项目 hours / 已知总 hours × coverage；coverage < 1 的残量
   保留为 project 为空的待分行，不向有记录者归一到 100%；无使用记录的月份
   当月分担全额待分。出资比例（funding）只解释预算承担，绝不代替 usage。

## 6. 组织时态

`organizations` 区间左闭右开。`OrgResolver` 提供两种解释：

- 历史视角（默认）：按业务月最后一天定位当时组织，负责人换组织后旧月不重写；
- 当前视角：按查询日定位当前组织（`--current-date`）。

资产后补归集与共享分担通过项目度量回连业务时点，因此旧月份始终能解释
"当时由谁负责"。

## 7. 装载、修订与管理包

- 每个装载目录形成一个 `load_batch`；相同 sha256 的文件记
  `duplicate_digest_skipped`，不增加事实。
- 同一记录键的新文件是**整行修订**：raw 追加新版本永不改写，
  事实计算按 `row_number() over (partition by 键 order by _batch desc, _row desc)`
  取视野内最新版本；`Warehouse.all_rows` 可审计全部历史版本。
- 事实层按批次全量重算（同批次重建=删除后替换，幂等）。
- 管理包是事实的冻结副本：`build` 生成草稿，`confirm` 后同一
  `(period, batch)` 拒绝重建；补资料后用新批次产生新包，
  `Packager.compare` 输出度量/行/例外的增减变化。

## 8. 事件视野

事实只覆盖已有业务事件覆盖到的月份（订单/收货/验收/单据/修订/usage
的最早月到最晚月）。后续批次带来更晚月份的数据时，新批次重建自动延伸
月份序列；已冻结管理包不受影响。
